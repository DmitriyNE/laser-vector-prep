# Development guide

## Stack

| Layer | Technology | Where |
|---|---|---|
| Geometry core | Rust, pure, host-testable (`proptest`) | `crates/lvp-core` |
| Browser bridge | Rust → WASM via `wasm-bindgen` | `crates/lvp-wasm` |
| UI / app shell | TypeScript, Vite, Web Workers | `web/` |
| Toolchain | Nix flake dev shell, `just` task runner | `flake.nix`, `justfile` |

The core never touches the DOM or wasm APIs; the wasm crate is a thin adapter that
moves flat `f64` buffers. The UI only ever talks to the core through a Web Worker.

## Prerequisites

[Nix](https://nixos.org/download) with flakes enabled (Determinate Nix has them on by
default). Nothing else: Rust, Node, `wasm-bindgen`, `wasm-opt` and `just` all come
from the flake. `direnv` users get the shell automatically from `.envrc`.

## Commands

All recipes run inside the dev shell. Either `nix develop` once and then call `just`,
or prefix each call with `nix develop -c`.

| Command | What it does |
|---|---|
| `just build` | One-shot production build: `npm ci`, release wasm + `wasm-opt`, type-check, Vite build → `web/dist/` |
| `just dev` | Debug wasm, then Vite dev server with hot reload |
| `just test` | `cargo test` (unit + property tests), type-check, `vitest` against the built wasm |
| `just regression` | Fixture-based `#[ignore]`d tests (see `fixtures/`) |
| `just lint` | `rustfmt --check` and `clippy -D warnings` (host and wasm targets) |
| `just wasm [release]` | Rebuild only the wasm + JS glue into `web/src/wasm/` (run after Rust changes while `just dev` is up) |
| `just preview` | Build, then serve `web/dist` locally |
| `just clean` | Remove build outputs |

`web/dist/` is a self-contained static site: deploy it to any static host, no headers
or server configuration required.

## Reproducibility

- Toolchain versions are pinned by `flake.lock`.
- Dependencies are pinned by `Cargo.lock` and `web/package-lock.json`.
- The `wasm-bindgen` crate is pinned exactly (`=x.y.z` in `Cargo.toml`) and must match
  `wasm-bindgen-cli` from nixpkgs. `just check-wasm-bindgen` (run automatically by
  `just wasm`) fails loudly if they drift. Bump `flake.lock` and `Cargo.toml` together.

## Cross-origin isolation and workers

Heavy geometry runs in Web Workers. To make `SharedArrayBuffer` available (shared wasm
memory / threads later), the page must be cross-origin isolated:

- Dev and preview servers send `Cross-Origin-Opener-Policy: same-origin` and
  `Cross-Origin-Embedder-Policy: require-corp` directly (`web/vite.config.ts`).
- The production bundle ships `coi-serviceworker.js` (copied from npm by `just coi`,
  referenced from `index.html`). On first load it registers a service worker that
  injects the same headers and reloads the page once. It must stay an unbundled,
  same-origin file.

The header in the running app shows `crossOriginIsolated` and `SharedArrayBuffer`
status so this can be checked at a glance.

## Layout

```
crates/lvp-core/      geometry core (geom, units, flatten, …) + proptests
crates/lvp-wasm/      wasm-bindgen exports
web/index.html        app shell, loads coi-serviceworker.js then src/main.ts
web/src/main.ts       UI entry
web/src/worker/       protocol.ts (messages), geometry.worker.ts, client.ts (promise façade, stale-result guard)
web/src/wasm/         generated by `just wasm` (git-ignored)
web/public/           static files copied verbatim into dist
docs/                 documentation (spec, this guide)
docs/engineering/     engineering log, todo, decisions, known defects
fixtures/             regression inputs and known-good outputs
```
